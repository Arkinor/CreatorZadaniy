# Создатель служб (Service Creator)

Небольшая программа для Windows 10/11, которая превращает `.exe`, `.bat`, `.cmd`,
`.ps1`, `.py`, `.vbs` и другие файлы в настоящую службу Windows. Все действия
выполняются из одного окна, а готовая программа поставляется одним файлом
`ServiceCreator.exe`.

## Возможности

- создание службы из любого файла с автоматическим подбором способа запуска;
- настройка аргументов, рабочей папки, переменных среды и приоритета процесса;
- типы запуска: автоматически, автоматически с задержкой, вручную, отключена;
- учётные записи LocalSystem, LocalService, NetworkService или пользовательская;
  для пользовательской учётной записи можно выдать право «Вход в качестве службы»;
- зависимости от других служб;
- автоперезапуск дочернего процесса с задержкой, ограничением числа попыток и
  отдельной настройкой «только при аварийном завершении»;
- действия Windows при сбое службы: перезапуск, перезагрузка, выполнение команды;
- журнал программы службы с дописыванием/очисткой и ограничением размера;
- список созданных служб, запуск, остановка, перезапуск, изменение и удаление;
- импорт и экспорт настроек в JSON;
- сворачивание в системный трей.

## Требования

- Windows 10 или Windows 11, x64;
- Python **3.11 x64** — только для сборки;
- права администратора — для создания, изменения и запуска служб.

Готовая программа Python не требует: интерпретатор и библиотеки упакованы в
`ServiceCreator.exe`.

## Сборка

1. Установите Python 3.11 x64 (при установке включите `Add Python to PATH`).
2. Запустите `build.bat` из папки проекта.
3. Скрипт создаст `.venv`, установит зависимости из `requirements.txt`, соберёт
   иконку и выполнит однострочную сборку PyInstaller.
4. Готовый файл появится здесь:

```text
dist\ServiceCreator.exe
```

`build.bat` использует `--onefile --windowed --uac-admin`, поэтому:
- рядом с `.exe` не требуется папка с библиотеками;
- консольное окно не открывается;
- Windows запрашивает повышение прав при запуске.

Если сборка запускается повторно, старые `build` и `dist` очищаются. В `dist`
остаётся только один клиентский файл — `ServiceCreator.exe`.

### Ручная сборка

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe tools\make_icon.py
.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onefile --windowed ^
  --uac-admin --name ServiceCreator --icon assets\app.ico ^
  --version-file tools\version_info.txt main.py
```

## Использование

1. Запустите `ServiceCreator.exe` и подтвердите запрос UAC.
2. Нажмите **«+ Создать службу»**.
3. Выберите файл, задайте отображаемое и внутреннее имя.
4. Проверьте вкладки **«Главное»**, **«Запуск»**, **«Восстановление»** и **«Журнал»**.
5. Нажмите **«Сохранить»**. При необходимости служба сразу будет запущена.
6. Управляйте службой кнопками **Запустить**, **Остановить**, **Перезапустить**,
   **Изменить** и **Удалить**.

Внутреннее имя службы после создания не меняется. Для новой службы используйте
латиницу, цифры, точку, дефис и подчёркивание.

### Где хранятся данные

```text
%ProgramData%\ServiceCreator\
├── configs\   настройки служб в JSON (без паролей)
├── host\      копия ServiceCreator.exe для запуска служб
└── logs\      журналы приложения и служб
```

Копия `ServiceCreator.exe` в `host` нужна, чтобы путь к исполняемому файлу службы
не зависел от того, откуда вы запустили клиент. Если переместить или удалить
исходный `ServiceCreator.exe`, уже созданные службы продолжат работать.

Пароли пользовательских учётных записей не сохраняются в JSON. Windows хранит их
в защищённой базе диспетчера служб. При изменении службы без смены учётной записи
пароль можно не вводить.

### Журналы

- `%ProgramData%\ServiceCreator\logs\app.log` — журнал интерфейса;
- `%ProgramData%\ServiceCreator\logs\<ИмяСлужбы>.log` — вывод программы службы;
- `%ProgramData%\ServiceCreator\logs\host.log` — диагностика хост-процесса.

Если папка `ProgramData` недоступна для записи, журнал приложения переносится в
`%LOCALAPPDATA%\ServiceCreator\logs`.

### Как это устроено

Служба Windows регистрируется с командной строкой:

```text
"C:\ProgramData\ServiceCreator\host\ServiceCreatorHost_<hash>.exe" --svc-host
```

Тот же самый файл работает и как графический клиент, и как хост службы. При
запуске службы он читает JSON-настройки, запускает выбранный файл дочерним
процессом, перенаправляет его вывод в журнал, следит за завершением и при
необходимости перезапускает. При остановке службы дочерний процесс завершается,
а если он не исчезает за отведённый таймаут — принудительно, при необходимости
вместе со своим деревом процессов.

## Ограничения

- Это обычная служба Windows. Она работает в сеансе 0, поэтому **окно программы,
  запущенной как служба, не будет видно на рабочем столе**. Предназначение
  программы — фоновые приложения, серверы, агенты и скрипты.
- Для службы из пользовательской учётной записи эта запись должна иметь право
  «Вход в качестве службы» и доступ к целевому файлу, рабочей папке и журналу.
- Службы не запускаются от имени текущего интерактивного пользователя. Если
  приложению нужен доступ к его профилю, укажите этого пользователя явно.
- Собранный `.exe` не подписан. SmartScreen или антивирус может показать
  предупреждение; для распространения используйте подпись кода.
- Удаление службы не удаляет целевой файл и журнал.
- Изменения настроек вступают в силу после перезапуска службы.
- Для действий с зависимостями и некоторыми системными службами могут требоваться
  дополнительные права.

## Диагностика

- Если служба не запускается, сначала откройте `host.log`: там есть команда
  запуска, рабочая папка, код завершения дочернего процесса и причина ошибки.
- Если Windows пишет «Служба не ответила вовремя», проверьте, что хост-процесс
  может запуститься от выбранной учётной записи, а целевой файл существует.
- Если не удаётся сохранить пользовательскую учётную запись, проверьте пароль и
  право «Вход в качестве службы» на вкладке **«Запуск»**.
- Если после сборки антивирус блокирует `.exe`, добавьте файл в исключения или
  подпишите его.

## Файлы проекта

```text
main.py                     точка входа GUI и хост-службы
service_creator/            логика приложения
service_creator/ui/         интерфейс Tkinter
assets/app.ico              иконка приложения
tools/make_icon.py          генерация иконки
tools/version_info.txt      версия и описание для PyInstaller
tools/e2e_service_test.py   проверка службы в реальном SCM (нужны права администратора)
requirements.txt            зависимости
build.bat                   сборка dist\ServiceCreator.exe
setup.bat                   установка окружения для разработки
```

## Самопроверка и снимки интерфейса

Для диагностики сборки предусмотрены служебные режимы:

```bat
.venv\Scripts\python.exe main.py --selftest --report %TEMP%\sc_selftest.txt
.venv\Scripts\python.exe main.py --screenshot %TEMP%\sc_shots
.venv\Scripts\python.exe main.py --version
```

Они не нужны для обычной работы.

Полная проверка службы в реальном диспетчере служб Windows выполняется из
командной строки с правами администратора:

```bat
.venv\Scripts\python.exe tools\e2e_service_test.py
```

Тест создаёт службу `SCTestE2E` с собранным хост-файлом из
`%ProgramData%\ServiceCreator\host`, запускает её, проверяет журнал и процесс
цели, перезапускает, останавливает и удаляет службу. При успехе следов не
остаётся; при ошибке файлы для диагностики сохраняются в
`%ProgramData%\ServiceCreator\logs\e2e`.
